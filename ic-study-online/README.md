IC Study online

The learning interface is preserved from the user-maintained IC_Study_Anime.html in source/study.html. A server account layer provides roles, generated student credentials and per-user progress sync.

Build: npm run build. Tests: npm test. Schema changes: npm run db:generate.

Sites provisions the DB D1 binding. The initial admin is provisioned from server-only IC_ADMIN_USERNAME and IC_ADMIN_HASH environment secrets; it is never taken from an anonymous browser claim. Passwords use salted PBKDF2 hashes. Session tokens use Secure HttpOnly cookies and are stored hashed. Password resets revoke sessions.

User/admin access checks run on every API request. Progress writes use revisions with automatic three-way reconciliation. Conflicting revisions fetch and merge current answers, per-question session choices, notes, bookmarks and plan checks before retrying. A per-account last-synced base preserves removals; old unsynced caches are migrated automatically. Visible tabs check for cloud updates every 15 seconds and on focus. The current question stays in place during study; network failures retain pending work and retry automatically. Original user wallpapers (PNG/JPEG/WebP/AVIF/GIF, up to 20 MiB) sync through a private per-account R2 object; small theme preferences sync with progress. IndexedDB retains an offline image cache. Existing cached images migrate on first web visit when the account has no wallpaper. Conditional writes prevent stale devices overwriting newer uploads, and resetting to the default leaves a tombstone so old caches cannot resurrect the image. Deleting a student also removes their image. The admin receives only summary data, not personal notes, wallpaper access to other accounts, or password hashes.

The upper-right Account menu contains optional backup and import tools for moving old HTML work into the account. Normal online use requires no export/restore. Sync status appears only in the upper right; the sidebar contains the independently scrolling navigation list.
